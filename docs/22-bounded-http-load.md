# 分级真实 HTTP 并发实验（本机、合成数据）

原先有进程内 TestClient 并发测试，但不能代表独立 HTTP 服务成本。新增 python -m scripts.load_http，启动自己的单进程 uvicorn，只访问 127.0.0.1 随机端口，使用独立临时 SQLite，忽略继承的数据库地址和代理，完成后关闭服务并清理临时库。没有外部 URL 参数，不向公网或已有服务施压。

固定 1/5/20 并发，每档 4 场景各 60 次，共 720 次测量请求（不含准备和查询）。请求超时 10 秒，线程与连接上限 20，不无限重试。

## 业务结果

每档：60 个独立请求创建 60 单；同键重试 60 次只生成 1 单；60 个不同键抢最后一件时 1 成功、59 库存不足；60 次重复取消只返还一次。最后 189 订单、12 合成商品，库存与流水对账通过。相同键下单重放现有 API 仍返回 201，不能把 201 响应数量当新增订单数。

## 解读与边界

这是短时、有界、闭环同机实验，不是持续到达的真实流量。吞吐包含库存不足等已完成响应，不等于成交量。延迟从工作线程发请求开始，不含线程池尚未开始执行任务的排队时间。每段只有60次，p99接近最慢一次，不能作为稳定SLO。共享云端CPU/磁盘使结果变化，不能从一次结果断言最大容量或并发必然提升吞吐。

幂等确保业务效果不重复，不阻止请求消耗线程、连接和查库。换幂等键仍可视为新请求。没有完成 DDoS、防机器人、恶意占库存、限流、多实例、PostgreSQL、持续负载或真实支付验证。下一步在明确业务到达率和延迟目标后做更长隔离实验，再设计限流/队列/有效期。不能写成“生产抗攻击已完成”。
