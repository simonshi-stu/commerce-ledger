# 04 数据来源与分阶段扩展

## 当前采用什么数据

app/seed.py 内 5 个 DEMO SKU 是为本项目手工生成的模拟商品。价格、库存和名称全部合成，不是市场报价，不代表原电商项目的真实采购成本或销量。没有姓名、电话、身份证、地址或客户 ID。没有复制酒店数据库。

这已经足够验证数据库约束、CRUD、缺货、订单幂等和取消；业务系统的初始库存与订单不能从任意公开销量数据集直接推断。

## 一个已经核查的公开候选来源

[UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail)（2026-11-03 核查，DOI 10.24432/C5BW33）。页面列出 CC BY 4.0 许可，引用格式：Chen, D. (2015). Online Retail [Dataset]. UCI Machine Learning Repository。

该数据包含 2010—2011 年英国零售交易。字段有 InvoiceNo、StockCode、Description、Quantity、InvoiceDate、UnitPrice、CustomerID、Country。UnitPrice 单位是英镑，InvoiceNo 以 c 开头表示取消。已核许可和字段语义，但**本次没有下载或导入**。

若下一阶段使用：

| 原字段 | 可用于什么 | 必须避免 |
|---|---|---|
| StockCode、Description | 脱离客户信息构造商品目录样例 | 假定每个描述永远稳定、代码全是纯数字 |
| UnitPrice | GBP 历史价格研究 | 直接当作本项目人民币分；隐含货币换算 |
| InvoiceNo、Quantity、InvoiceDate | 独立历史分析库中的交易重放候选 | 把负数量/取消行当正向新订单 |
| CustomerID、Country | 本原型不需要，导入时直接丢弃 | 引入客户标识或伪造联系人 |
| 不存在的库存字段 | 单独生成并标注模拟库存 | 把销量当库存、假称拥有仓储数据 |

先制定筛选与映射规则，再检查空值、重复行、同码多描述、负数/零价格、取消单、时区、数量范围、货币。不要只依赖数据页的缺失值标签。保留来源、许可链接、清洗脚本版本及输入校验和；导出衍生目录时注明改动与 CC BY 4.0 署名。真实交易分析应放在独立只读分析库，不混入教学业务订单。

没有必要为了简历“数据集”而拉取大量不适配字段。本阶段优先保证可解释与可重复。

## 阶段与验收条件

1. **当前已实现：最小闭环。** 五表、商品 CRUD（删除为下架）、库存调整/流水、多商品下单、价格快照、幂等、取消/履约状态、错误处理、种子与自动测试。用户已确认使用 Python；SQLite 是第一阶段数据库。
2. **下一阶段：数据库深化。** 保留 Python，升级 PostgreSQL 或 MySQL，加入目标引擎迁移、集成测试和事务隔离解释。验收：同一业务用例在目标数据库通过。
3. **再下一阶段：权限与实际业务扩展。** 密码哈希、登录/RBAC、库存盘点、分页过滤、补货单、订单到期策略。验收：权限矩阵与状态转换测试；过期任务幂等，不重复返库存。
4. **选做：数据与性能。** 核准公开目录导入、索引与 EXPLAIN、可重复压测、日志与指标。验收：报告环境、数据量、错误率和延迟，不编造生产 QPS。
5. **最后再考虑：接入真实平台。** 当前未授权且未实现；涉及真实店铺/支付需另外设计权限、回调验签和审计，不属于本次本地项目。

先把第一阶段讲清楚，比一次加 Redis、消息队列、微服务更有助于应对追问。后续组件应当由明确问题驱动。
